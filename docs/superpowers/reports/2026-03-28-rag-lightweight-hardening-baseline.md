# 面试 RAG 轻量生产化基线报告

## 当前 dense 基线是否稳定

当前结论：**基本稳定，但仍只足够支持“验证可跑通”**。

- 现有评测已经证明 dense 主召回能够覆盖多数理论题、场景题和技术钩子型项目题。
- 行为题依赖题型路由和领域留空策略，不能只看 dense 命中率。
- 当前 dense 仍然值得保留为主召回路径，不需要推翻重做。

## 当前候选是否足以支撑默认商业 rerank

当前结论：**可以支撑，但要先把 lexical 路清理成更干净的预过滤。**

- 现在的候选集已经能把目标题卡大体召回出来。
- 当前主要短板不是“完全召回不到”，而是候选里仍混有低质量或不够贴题的卡片。
- 商业 rerank 适合作为下一阶段默认精排，但前提是把当前 `scroll + keywordScore` 假 sparse 路替换掉。

## 当前最容易退化的题型

当前最容易退化的是两类：

1. **行为题**
- 最容易被技术题污染。
- 程序侧必须保留题型和污染护栏，不能把判断责任全部甩给出题模型。

2. **技术钩子型项目题**
- 最容易从项目深挖退化成泛八股。
- 必须保住项目锚点、技术关键词和项目上下文。

## 当前瓶颈判断

当前主要瓶颈不是 dense 主召回本身，而是：

- lexical 路仍然是假实现
- 规则重排过于依赖字面匹配
- 最终排序质量还不够稳定

## 下一阶段建议

下一阶段优先级：

1. 把假 sparse 改成 Qdrant lexical 预过滤
2. 保留 dense 作为主召回
3. 接商业 rerank 做默认主排序
4. 把程序规则收缩成硬护栏

## 最小审计字段

当前轻量生产化版本要求在检索链路里稳定记录下面这些字段：

- 是否触发检索
- lexical prefilter 后候选数
- dense 候选数
- rerank 前 top ids
- rerank 后 top ids
- 最终注入题卡 ids

这些字段会通过 `retrievalAudit` 挂到 RAG 上下文里，供：

- `questionGenerationInput` 调试快照
- 问题回放排查
- 人工抽样核查

## 人工抽样审查模板

抽样建议：

- 理论题 3 条
- 场景题 3 条
- 行为题 2 条
- 项目题 3 条
- 负样本 1 条

每条样本统一按下面模板记录：

1. 是否触发检索
2. `retrievalAudit` 是否合理
3. 注入题卡是否合理
4. 最终问题是否更自然
5. 是否出现八股漂移
6. 是否出现技术污染
