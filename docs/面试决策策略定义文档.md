# 面试决策策略定义文档

本文整理当前面试引擎里“评估回答后选择下一步动作”的全部策略定义，供后续按文档改策略。

这份文档不是当前运行时真源。当前代码真源仍然在：

- `backend/src/main/java/com/a05/aiinterview/ai/contract/StrategyCatalog.java`
- `backend/src/main/java/com/a05/aiinterview/interview/engine/AvailableStrategyAssembler.java`
- `backend/src/main/java/com/a05/aiinterview/ai/impl/OpenAiClient.java`

你后续如果修改本文档，我会再按文档把代码同步过去。

## 1. 建议你优先改哪一层

如果你的目标是“让模型更清楚每个决策是什么意思”，优先改下面这些字段：

- `label`
- `description`
- `applicableWhen`

原因：

- 运行时注入给 AI 的 `availableStrategies` 里，真正会给模型看的核心字段就是这 3 个，再加上 `strategyCode`、`moveType`、`requiresTargetDomain`
- 其中 `description` 会被格式化成 Prompt 里的“意图”
- `applicableWhen` 会被格式化成 Prompt 里的“适用条件”

如果你的目标是“改变策略是否合法、什么时候能出现、执行后怎么计数”，再改这些运行时约束字段：

- `moveType`
- `allowedCurrentQuestionTypes`
- `targetQuestionType`
- `requiresTargetDomain`
- `requiredContext`
- `blockingLimits`
- `samePointFollowUp`
- `quotaUpdatePolicy`
- `wrapup`

## 2. 字段说明

### 2.1 AI 可见字段

| 字段 | 含义 | 当前是否直接给 AI |
| --- | --- | --- |
| `strategyCode` | 策略编码，AI 最终输出到 `finalDecision` | 是 |
| `label` | 策略名称 | 是 |
| `description` | 策略意图说明 | 是 |
| `applicableWhen` | 策略适用条件 | 是 |
| `moveType` | 策略动作类型 | 是 |
| `requiresTargetDomain` | 是否必须带 `targetDomainCode` | 是 |

### 2.2 运行时约束字段

| 字段 | 含义 |
| --- | --- |
| `allowedCurrentQuestionTypes` | 该策略允许从哪些当前题型发起 |
| `targetQuestionType` | 该策略执行后，下一题目标题型 |
| `requiredContext` | 该策略出现前必须满足的上下文要求 |
| `blockingLimits` | 命中这些配额上限后，该策略不会进入本轮 `availableStrategies` |
| `samePointFollowUp` | 是否被系统视为“同一点连续追问”；若是，会推进 `samePointContinue` |
| `quotaUpdatePolicy` | 执行该策略后，各配额计数如何增加或重置 |
| `wrapup` | 是否为结束策略 |

### 2.3 动作类型 `moveType`

| 值 | 含义 |
| --- | --- |
| `ADVANCE` | 在当前主线上继续向前推进 |
| `SWITCH` | 不换大题型，但切换焦点/样本/项目 |
| `ENTER` | 切换到另一种题型 |
| `END` | 结束面试 |

### 2.4 上下文要求 `requiredContext`

| 值 | 含义 |
| --- | --- |
| `PROJECT_CONTEXT` | 必须存在项目上下文，否则该策略不会进入合法策略池 |

### 2.5 配额键 `StrategyLimit`

| 键 | 含义 |
| --- | --- |
| `samePointContinue` | 同一点连续追问次数 |
| `sameDomainContinue` | 同一理论域连续推进次数 |
| `sameProjectPointContinue` | 同一项目要点连续追问次数 |
| `sameProjectContinue` | 同一项目连续推进次数 |
| `principleTotal` | 理论题总量 |
| `projectTotal` | 项目题总量 |
| `scenarioTotal` | 场景题总量 |
| `behavioralTotal` | 行为题总量 |

### 2.6 `quotaUpdatePolicy` 记法

本文中的 `quotaUpdatePolicy` 使用统一写法：

- `inc:` 表示执行后递增的计数
- `reset:` 表示执行后重置为 0 的计数
- `clearSourceContinuousCounters:` 表示是否先清空来源题型的连续计数

示例：

- `inc: samePointContinue, sameDomainContinue, principleTotal; reset: 无; clearSourceContinuousCounters=false`
- `inc: principleTotal; reset: 无; clearSourceContinuousCounters=true`

## 3. 运行时链路

### 3.1 权威真源

- 所有策略定义真源：`StrategyCatalog.buildDefinitions()`

### 3.2 注入给 AI 的字段

- `AvailableStrategyAssembler.toInput()` 只会把以下字段注入给 AI：
  - `strategyCode`
  - `label`
  - `description`
  - `applicableWhen`
  - `moveType`
  - `requiresTargetDomain`

### 3.3 Prompt 中的呈现方式

`OpenAiClient.formatAvailableStrategies()` 会把每条策略格式化成：

- 标题：`label`
- `StrategyCode`
- 意图：`description`
- 适用条件：`applicableWhen`

### 3.4 本文如何阅读

- 如果你主要想修“模型为什么理解错这个决策”，先看每组里的“可编辑详细信息定义”
- 如果你还想修“为什么某策略会出现/不会出现/执行后怎么计数”，再看每组里的“运行时约束快照”

## 9. 与当前代码行为直接相关的注意点

### 9.1 哪些字段真正影响模型理解

当前最直接影响模型如何理解某个决策的，是：

- `label`
- `description`
- `applicableWhen`

因为这 3 个字段会原样进入 `availableStrategies` 文本。

### 9.2 哪些字段不会直接给模型看

以下字段主要影响后端筛选与校验，不直接展示给模型：

- `allowedCurrentQuestionTypes`
- `requiredContext`
- `blockingLimits`
- `quotaUpdatePolicy`
- `wrapup`

### 9.3 如果后续要把“文档改动”落实进代码

通常会涉及这些位置：

- 文案类变更：`StrategyCatalog.java`
- 合法策略池筛选：`AvailableStrategyAssembler.java`
- Prompt 呈现结构：`OpenAiClient.java`
- 输出校验：`DecisionExecutionPlanBuilder.java`

## 10. 建议修改方式

如果你准备先改文档再让我落代码，建议你按下面顺序改：

1. 先改各策略的 `label / description / applicableWhen`
2. 再决定是否要改 `moveType`
3. 最后再改 `blockingLimits / samePointFollowUp / quotaUpdatePolicy`

原因：

- 第 1 步主要影响“模型怎么理解动作”
- 第 2 步影响“动作在面试流程里属于推进、平移、切换还是结束”
- 第 3 步影响“动作什么时候能出现、连续追问怎么计数、配额怎么推进”

如果你只想先解决“同域平移定义不清”的问题，通常先改：

- `S_P_VERIFY`
- `S_P_DEEP_LINK`
- `S_P_VARIANT`
- `S_P_SAME_DOMAIN_SHIFT`
- `S_SWITCH_DOMAIN`
