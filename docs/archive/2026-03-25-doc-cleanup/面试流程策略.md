# 面试流程策略（归档版，已按当前口径改写）

这份归档文档只保留当前仍然有效的流程结论，避免历史错误术语继续污染主设计。

## 核心结论

- 候选人资历使用 `experienceLevel`
- 题目深度使用 `difficulty`
- 当前轮目标深度提示使用 `difficultyHint`
- 知识域唯一身份使用 `domainCode`
- 展示层使用 `domainName`

## 当前主链路

1. 创建面试时生成一次 `syllabusJson`
2. `planner` 只规划知识域和项目切入点
3. `stateLedgerJson` 作为运行态唯一过程状态
4. `evaluation-decision` 只消费结构化上下文，不再依赖旧知识域主键
5. `question_generation` 只根据当前策略和检索结果出题

## Java 后端知识域

当前 `JAVA_BACKEND` 固定为 10 个知识域：

- `java_core`
- `concurrency`
- `jvm`
- `mysql`
- `redis`
- `spring`
- `mq`
- `microservice`
- `distributed`
- `cs_basics`

## 账本约束

- `domain_states[*].domainCode` 是运行态唯一知识域身份
- `covered_domains[*]` 必须是结构化对象
- 非法编码和脏字符串按异常处理，不做模糊修复

## 结果输出

- 明细评价按题型与 `domainCode` 组织
- 报告展示层可再映射中文名
- 不再保留旧知识域主键相关描述
